# [Specs] MoSCoW 기반 기능명세서

## 1. 기능 설계 원칙 및 MoSCoW 기준

본 명세서는 1030 보행자의 핵심 문제인 **"차 없이 안전하고 힙한 독립 골목길을 찾아 쾌적한 나들이 동선을 짠다"**를 해결하기 위해 작성되었으며, 기능 비대화(Feature Creep)를 막기 위해 아래의 MoSCoW 기준으로 단계를 나누었습니다.

*   **Must Have (필수):** 15초 일반 유저 시나리오 수행 및 MVP 웹앱 출시에 반드시 필요한 기능.
*   **Should Have (권장):** 보행 유저의 편의성 및 동선 공유 기능을 극대화하는 중요 기능.
*   **Could Have (선택):** 향후 고도화 단계에서 추가 가능한 부가 기능.
*   **Won't Have (v1 제외):** 이번 1차 웹 서비스 구현 범위에서는 명확히 제외하는 기능.

## 3. 상세 기능 요구사항 명세

### F-01. 서울 '로컬 힙 보행 지수' 지도 홈 (Must Have)
*   **Processing:** 보행자전용도로 비중, 차량제한구역 여부, 소규모 독립점포 수 데이터를 결합하여 연산된 '로컬 힙 보행 지수(0~100점)' 데이터를 Mapbox 레이어로 렌더링함.
*   **Output:** 접속 3초 이내에 1030 타겟이 선호하는 힙스터 골목 구역들이 핑크/오렌지색 계열의 은은하게 빛나는 '블러 도넛' 형태의 핫스팟 마커 형태로 표출되어야 함.

### F-02. 보행자 맞춤형 조건 필터바 (Must Have)
*   **Input:** 
    *   **대형 프랜차이즈 완전 제외** (On/Off 토글스위치, 기본값 On)
    *   **선호 업종 다중 선택** (감성 카페 / 이색 소품샵 / 독립 서점 / 편집숍 등, 체크박스 UI)
    *   **보행 쾌적도 가중치** (0% ~ 100%, 슬라이더 UI, 기본값 50%)
    *   **독립상점 밀집비율** (0% ~ 100%, 슬라이더 UI, 기본값 50%)
*   **Processing:** 
    *   사용자가 토글, 체크박스, 슬라이더를 조작하는 즉시 클라이언트 세션 또는 백엔드 API에서 가중치가 적용된 실시간 **'로컬 힙 보행 지수(Local Hip Walk Score)'** 재연산 알고리즘을 수행함.
    *   체크박스로 선택된 업종 데이터가 누적되어 밀집 비율 가산점에 실시간 반영됨.
*   **Output:** 필터 조작 후 1초 이내에 연산이 완료되어, 지도 홈 화면의 **'블러 도넛' 형태 핫스팟 마커들의 크기와 색상 농도가 실시간으로 동적 갱신(Update)**되어야 함.
*   **UI/UX:** 화면 상단 또는 우측 레이어에 Floating 디자인으로 배치하며, 슬라이더 조작 시 현재 설정 값이 숫자로 직관적으로 표시되는 모던한 슬릭 UI 적용.

### F-03. 골목 구역(Polygon) 하이라이트 & 3초 요약 카드 (Must Have)
*   **Input:** 지도 화면에 표출된 특정 '블러 도넛' 마커 터치 또는 하위 골목 다각형(Polygon) 영역 마우스 클릭.
*   **Processing:** 해당 공간 구역 ID(Spatial ID)에 매핑된 세부 속성 데이터(실질 인도 분리도 %, 보행자 우선도로 지정 여부, 사용자가 선택한 업종 기반의 대표 독립 상점 탑 3 리스트, 인스타그램 감성 키워드 등)를 매핑 테이블에서 고속 조회함.
*   **Output:** 
    *   선택된 골목 구역의 바닥면 경계(Polygon)가 은은한 핫핑크/네온 외곽선으로 두껍게 하이라이트 표시됨.
    *   동시에 화면 하단에서 슬라이딩 업(Sliding-up) 방식으로 **3초 요약 팝업 카드**가 노출됨.
*   **UI/UX:** 
    *   요약 카드 내에 **종합 보행 점수(Score)**를 감성적인 그래픽 배지로 크게 노출함.
    *   "차 없이 마음 편히 걷는 청정 골목", "아기자기한 소품샵 천국" 등 인스타 태그 스타일의 핵심 문구 노출.
    *   대표 독립 상점 3곳의 미니 썸네일 이미지 및 "이 골목 탐방 코스 추천받기" 버튼 배치.

### F-04. 1클릭 골목 탐방 코스 추천 및 공유 (Should Have)
*   **Input:** 요약 카드 내 "이 골목 탐방 코스 추천받기" 버튼 클릭 및 "카카오톡 공유하기" 아이콘 클릭.
*   **Processing:** 
    *   해당 골목 폴리곤 내부의 **보행자 전용 도로망 네트워크 데이터**와 상점들의 위치(위경도 좌표)를 기반으로, 차량 통행 스트레스를 최소화하며 필수 핫플 상점들을 유기적으로 순회할 수 있는 가장 예쁜 도보 나들이 루트 라인(LineString)을 연산함.
    *   현재 동선의 고유 상태값(선택된 골목 정보 및 코스 좌표)을 파라미터화한 카카오톡 공유 Web 링크 스크립트를 생성함.
*   **Output:** 
    *   지도 상에 핫스팟 마커들을 부드럽게 연결하는 **파스텔톤의 나들이 추천 코스 실선 라인**이 즉시 오버레이되어 드로잉됨.
    *   공유 버튼 클릭 시 외부 카카오톡 공유 API 창이 팝업되며 공유 완료 시 화면 내 토스트(Toast) 알림이 뜸.

### F-05. 주변 골목 쾌적도 비교 분석 (Could Have)
*   **Input:** 요약 카드 하단의 "주변 유사 골목과 비교하기" 버튼 클릭 또는 지도상에서 2개 이상의 골목 구역을 다중 선택.
*   **Processing:** 선택된 골목들의 공간 데이터를 대조하여 보행 안전성, 프랜차이즈 역비율, 독립 상점 다양성, 인스타그램 바이럴 지수 등 4~5개 주요 핵심 축의 정량적 지표를 추출함.
*   **Output:** 화면 측면 또는 하단 팝업 창에 보행자가 직관적으로 비교할 수 있는 투명한 **레이더 차트(Radar Chart) 컴포넌트**를 표출하여 어떤 골목이 더 한적하고 아기자기한지 시각적 가이드 제공.
