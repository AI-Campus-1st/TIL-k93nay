# [PTS] 제품 테스트 명세서 (QA Test Specification)

본 문서는 `02_user_scenario.md`의 보행자 나들이 여정과 `03_functional_specs.md`의 기능 명세를 바탕으로, 일반 유저가 주말에 서비스를 이용할 때 발생할 수 있는 주요 시나리오를 배포 전 검증하기 위한 QA 테스트 케이스 매트릭스입니다.

## 1. QA 테스트 케이스 매트릭스 (Test Cases)

| 테스트 ID | 검증 대상 기능 | 테스트 시나리오 및 절차 | 합격 기준 (Pass Criteria) | 우선순위 |
| :--- | :--- | :--- | :--- | :---: |
| **TC-01** | **F-01: 보행자 지도 홈 로딩** | 1. 뚜벅이 유저가 모바일 브라우저로 서비스 주소에 진입한다.<br>2. 서울 전체 지도 화면을 확인한다. | • 접속 후 **3초 이내**에 서울 전체 '로컬 힙 보행 지수' 레이어가 정상 로딩되어야 함.<br>• 골목 구역들이 핑크/오렌지색 계열의 **은은하게 빛나는 '블러 도넛' 형태의 핫스팟 마커** 형태로 정상 표출되어야 함.<br>• 화면 내 범례가 표시되어야 함. | **High** |
| **TC-02** | **F-02: 테마/가중치 필터 조작** | 1. '대형 프랜차이즈 완전 제외' 토글을 On으로 켠다.<br>2. 선호 업종 체크박스에서 '이색 소품샵'을 다중 선택한다.<br>3. 보행 쾌적도 및 독립상점 밀집비율 슬라이더를 조작한다. | • 필터 및 슬라이더 조작 완료 후 **1초 이내**에 API 응답 데이터를 수신해야 함.<br>• 수신 데이터에 맞춰 지도 상의 **'블러 도넛' 핫스팟 마커들의 크기와 색상 농도가 실시간으로 동적 갱신(Update)**되어야 함. | **High** |
| **TC-03** | **F-03: 마커 터치 및 요약 카드** | 1. 지도상에서 가장 크고 붉게 활성화된 특정 '블러 도넛' 마커를 터치한다. | • 선택된 골목 구역의 바닥면 경계(Polygon)가 **은은한 핫핑크/네온 외곽선으로 두껍게 하이라이트** 표시되어야 함.<br>• 동시에 화면 하단에서 슬라이딩 업(Sliding-up) 방식으로 **3초 요약 팝업 카드**가 노출되어야 함. | **High** |
| **TC-04** | **F-04: 추천 코스 라인 생성** | 1. 활성화된 요약 카드에서 '이 골목 탐방 코스 추천받기' 버튼을 누른다.<br>2. 지도상에 그려지는 동선을 확인한다. | • 해당 골목 내부 보행 도로망을 연결하는 **파스텔톤의 나들이 추천 코스 실선 라인(LineString)**이 지도 위에 정확히 오버레이되어 드로잉되어야 함.<br>• 차량 전용 대로변으로 우회하는 경로가 없어야 함. | **High** |
| **TC-05** | **F-04-공유: 카카오톡 링크 공유** | 1. 생성된 추천 코스 화면에서 '카카오톡 공유하기' 아이콘을 누른다.<br>2. 공유된 링크를 카카오톡 대화방에 전송하고 클릭하여 재진입해 본다. | • 아이콘 클릭 시 외부 카카오톡 공유 API 창이 정상 팝업되며, 완료 시 화면 내 토스트(Toast) 알림이 떠야 함.<br>• 공유된 링크로 재접속 시, 사용자가 세팅했던 골목 구역과 추천 동선 라인이 깨짐 없이 그대로 재현되어야 함. | **Medium** |
